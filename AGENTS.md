# AGENTS.md

Guidance for coding agents working in this repository. The [README](README.md) covers what the cartridge is and how to build it; this file covers what you need to know before changing it.

## What this is

[dval.dev](https://dval.dev) as a Game Boy Advance ROM, built with [PocketJS](https://github.com/pocket-nexus/pocketjs). MicroTS compiles a Solid TSX view and a TypeScript model to `no_std` Rust for the GBA's ARM7. No JavaScript runs on the cartridge, and nothing can be fetched at runtime: all content is baked into the ROM at build time.

## Commands

| Command                            | What it does                                                               |
| ---------------------------------- | -------------------------------------------------------------------------- |
| `bun run setup`                    | Fetch the PocketJS submodule and install its dependencies (once per clone) |
| `bun run sync ../dval.dev`         | Re-lift content and images from a dval.dev checkout                        |
| `bun run build`                    | Generate `app/app.tsx` and `app/pages.ts`, then build `dist/dval-gba.gba`  |
| `bun run typecheck`                | `tsc` over the scripts, art and app                                        |
| `bun run preview`                  | Play the ROM headlessly in libmgba and refresh `docs/screenshots/`         |
| `bun scripts/screenshots.ts --all` | Capture every page into `.build/all-pages/`                                |
| `bun run format`                   | Format everything with Prettier (`format:check` only checks)               |

The build needs Rust stable (for the desktop baker), `nightly-2026-07-01` with `rust-src` (for the cartridge) and the `wasm32-unknown-unknown` target. `preview` needs libmgba (`apt install libmgba-dev`).

## Where things live

- `content/site.json` is generated by `scripts/sync-content.ts` from the website: projects, roles, intro, principles, contact links. Don't edit it by hand. Put cartridge-only copy in `content/overrides.json` (see the README).
- `assets/portrait.png` and `assets/projects/*.png` are also written by the sync. `assets/fonts/` holds the Press Start 2P WOFF and its OFL license.
- `scripts/content.ts` declares the shape of `site.json` and `overrides.json`. `scripts/pixels.ts` holds the image helpers the sync and the art build share (decode, area-average, k-means, PNG output).
- `scripts/gen-app.ts` turns `site.json` into `app/app.tsx` (the view) and `app/pages.ts` (page indices, plus `SECTION_START` and `SECTION_PAGES`, which locate each menu section's pages). Both outputs are generated, formatted with Prettier and committed: change the generator, then run `bun run build`, and commit the regenerated files with it. The menu's sections and their order are the `SECTIONS` list in the generator; the model reads them from the tables, so adding a section needs no model change.
- `app/app.ts` is the hand-written model: the `page` signal and the button handlers (`confirm`, `back`, `up`, `down`, `next`, `previous`).
- `art/sprites.ts` holds the hand-drawn sprites as character grids, one character per pixel, keyed to the Sweetie 16 palette in `art/palette.ts`. `scripts/art.ts` renders them, plus the contact QR code, to PNGs at build time.
- `scripts/fonts.ts` turns the one WOFF into the two faces PocketJS bakes: a regular face with its em rescaled so `text-xs` draws at 1×, and the original as bold so `font-bold text-base` draws at 2× and `font-bold text-2xl` at 3×.
- `host/` is PocketJS's GBA host, copied and modified. `host/README.md` lists every change from upstream; keep that table current if you touch `host/`.
- `vendor/pocketjs` is a submodule pinned to a commit. Don't edit it; change `host/` instead.

## How the screen works

The chrome (header bar, window frame) is one static tile background. Everything else is a sprite layer:

- `Screen` holds every page as a `<Show when={page() === N}>` branch. The desktop baker renders each branch to a 224 × 128 frame, and the cartridge DMA-copies the active frame into sprite memory when `page()` changes.
- `Beat` is the two-frame heart in the header, toggled by `pulse()` in the model.

The generator lays pages out in absolute screen pixels on an 8 px grid. Press Start 2P is monospaced, so a line of text is `length × 8 × scale` px wide, and wrapping counts characters, not measured widths.

## Rules the build enforces (or the cartridge breaks on)

- **Every page's first element must be text that no other page starts with.** The presenter identifies the mounted branch by its first element. `gen-app.ts` throws if two pages collide.
- **Everything at the top level of a branch is `absolute`, with a constant position and size.** Text gets an explicit `w-[…] h-[…]`; `emit()` in `gen-app.ts` does this for you.
- **Page content stays inside the content area**, from x 16 to 224 and y 26 to 153. `gen-app.ts` throws otherwise.
- **Textures are power-of-two sizes** (16, 32, 64, …). Anything else fails an assertion during the bake.
- **Sprite budget: 128 OAM entries and 32 KiB of sprite VRAM.** One page frame costs 56 OAM and 28 KiB, so only about 3 KiB is left for anything else that animates. `host/assets.ts` fails the build when a change goes over.
- **One shared 256-color sprite palette**, built by median cut over every frame. The UI and logos use Sweetie 16, and the portrait adds its own 16 colors (32 in use now). Keep new art to the palette or a small set of colors, or the median cut will start merging colors.
- **Images are found by name.** An `<Image src="x.png">` resolves against `.build/art/` (generated sprites) and then `assets/`.
- **The model is MicroTS, not general TypeScript.** It compiles to Rust, so numbers need a fixed width: function parameters and signals are typed `i32` from `@pocketjs/framework/solid/std`, and the build runs in strict mode, which rejects plain `number`. An integer literal such as `const MENU = 1` infers `i32` without an annotation. Keep to named functions, signals, `if`/`switch`/`for` and module constant arrays (lookups compile to static Rust arrays); `Record`, `Map`, classes, closures stored as values and methods like `.map` are not available. There is no `<For>`, storage, audio or network on this target. The [MicroTS TypeScript reference](vendor/pocketjs/site/content/docs/typescript-support.md) lists the full subset.

## Code style

Prettier formats every file, with the same settings as dval.dev (no semicolons, single quotes, 80 columns). Beyond formatting: one declaration per line, braces on any `if` or `for` whose body spans lines, named constants for layout numbers and hardware values, and shared helpers instead of copied loops.

## Checking a change

1. `bun run typecheck` and `bun run format:check`
2. `bun run build`. Read the budget line it prints (`OAM …/128, OBJ VRAM …/32768 B`).
3. `bun run preview`, then look at the screenshots. The runner exits with an error if the ROM faults. For a new or changed page, run `bun scripts/screenshots.ts --all` and check every page, not just the tour.

With `DIAG=1` set, `tools/shots.c` also prints the 32 diagnostic words the host writes at the start of EWRAM (0x02000000). `host/src/main.rs` writes them with `diag(index, value)`. Word 2 is `0xdead` after a fault and word 13 holds the fault code. Word 5 is the last frame's cycle count and word 6 the peak, word 7 counts missed frames, word 9 is peak heap and word 20 is stack use.

Commit the regenerated `app/` files and any screenshots that changed alongside the source change that produced them. The ROM itself (`dist/`) and `.build/` are not committed.
